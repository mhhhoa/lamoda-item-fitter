# Lamoda Item Fitter

Приводит предметные фото обуви к требованиям Ламоды: холст **1524 × 2200**, отступы
**200 сверху, 360 снизу, по 200 с боков**, товар обязательно стоит на нижней линии отступа
и отцентрован по горизонтали.

Программа рассчитана на коллег, которые с компьютером на «вы»: скачал `exe`, запустил двойным
кликом, перетащил папку, нажал «Обработать». Устанавливать Python и что-либо ещё не нужно.

## Как пользоваться

1. Перетащите в окно файлы или папку — можно сразу несколько. Папки обрабатываются со всей
   вложенностью.
2. Нажмите **Обработать**.
3. Готовые файлы появятся в папке **Загрузки**.

Куда именно ложится результат:

| Что загрузили | Куда попадёт |
|---|---|
| Отдельные файлы | `Загрузки/имя_lamodafit.jpg` |
| Папку | `Загрузки/имя папки/имя_lamodafit.jpg`, вложенность сохраняется |

Если файл с таким именем уже есть, программа **спросит** — перезаписать, сохранить копией
или пропустить. Молча ничего не затирается.

Клик по строке в списке открывает превью с направляющими: красная рамка — поля, зелёная
линия — нижний отступ. По ним сразу видно, что товар стоит правильно.

### Что означают статусы

| Статус | Что произошло |
|---|---|
| **готово** | Кадр подогнан по правилам |
| **перенесён без подгонки** | Макро-кадр: товар намеренно выходит за край, вписать его по габариту нельзя. Если исходник уже 1524 × 2200, он просто переложен в папку результата с суффиксом |
| **пропущен** | Подогнать не удалось — причина в подсказке к строке |
| **ошибка** | Файл не открылся или не сохранился |

Замечания (наведите курсор на статус): тёмный фон, обрезанный краем товар, сильное увеличение
мелкого исходника, нечёткие границы. Это не ошибки, а повод посмотреть результат глазами.

## Где взять exe

Сборка идёт автоматически на GitHub Actions при каждом пуше.

* **Свежая сборка:** вкладка **Actions** → последний зелёный запуск → раздел **Artifacts** →
  `LamodaItemFitter-windows`. GitHub отдаёт артефакт zip-архивом, внутри лежит `exe`.
* **Релиз:** пуш тега вида `v1.0` создаёт черновик релиза с приложенным `exe` — удобно, когда
  нужно дать коллегам прямую ссылку.

## Правила меняются без пересборки

Все требования маркетплейса лежат в [`presets/lamoda.json`](presets/lamoda.json). Программа
сначала ищет файл `lamoda.json` **рядом с exe** и только потом берёт встроенный, поэтому
поправить отступы или формат можно, положив свой файл в ту же папку.

```json
{
  "canvas":  {"width": 1524, "height": 2200},
  "margins": {"top": 200, "bottom": 360, "left": 200, "right": 200},
  "output":  {"format": "jpeg", "jpeg_quality": 100, "max_bytes": 5242880}
}
```

## Командная строка

Нужен Python 3.12 и `pip install -r requirements.txt`.

```bash
# подогнать папку или файлы
python -m lamoda_item_fitter fit ПАПКА --out ./out
python -m lamoda_item_fitter fit фото1.jpg фото2.jpg --format png
python -m lamoda_item_fitter fit ПАПКА --on-conflict overwrite

# замерить уже опубликованные фото и выверить пресет
python -m lamoda_item_fitter analyze reference/ --md отчёт.md --json данные.json
```

## Откуда взялись правила

Пресет не придуман, а измерен. В [`reference/`](reference) лежат 19 фото трёх артикулов,
уже прошедших модерацию Ламоды; команда `analyze` меряет их и выдаёт цифры, а
[`tests/test_reference.py`](tests/test_reference.py) следит, чтобы правки алгоритма с ними
не расходились.

Что показали эталоны:

* Холст ровно 1524 × 2200 во всех 19 файлах.
* Фон — **249, 249, 249** и идеально ровный, а не чистый белый. Поэтому программа заливает поля
  цветом фона исходника, а не белым, и мягко выравнивает фон, убирая шум и стык вставки.
* Нижний отступ по подошве — 312…360 (Ламода выравнивает вручную). У двух кадров плотная кромка
  подошвы стоит ровно на `y = 1839`, то есть отступ ровно 360; на это выравнивание мы и опираемся.
* Товар **всегда** занимает всю ширину рабочей зоны — при любом ракурсе. Вид сбоку, пара 3/4,
  вид сверху и подошва растянуты по ширине одинаково, поэтому никаких коэффициентов по ракурсам
  не нужно, а масштаб между ракурсами одного артикула Ламода не согласовывает.
* Настоящих падающих теней в эталонах нет: разница габарита между самым мягким и самым жёстким
  порогом — 8…16 px, то есть это край подошвы, а не тень.
* Почти половина галереи (9 из 19) — макро-кадры, намеренно выходящие за края холста.

Прогон самих эталонов через программу даёт ровно 360 снизу и не ближе 200 к краям при
изменении масштаба всего на 1…8 %.

## Как это работает

1. **Фон.** Цвет берётся как медиана по рамке в 2 % кадра — медиана не сдвигается, даже если
   товар подходит вплотную к краю.
2. **Порог.** Считается от собственной изменчивости фона: товар — это всё, что отличается от фона
   сильнее, чем фон отличается сам от себя. Фиксированный высокий порог срезал бы светлую подошву
   на светлом фоне, а порог по Оцу отвечает не на тот вопрос.
3. **Маска.** Смыкание разрывов, заливка дыр, отбрасывание компонентов мельче 2 % крупнейшего —
   так уходят пыль и подписи, а пара обуви из двух предметов остаётся целиком.
4. **Тень.** Мягкая затухающая тень отличается от ровной светлой подошвы по вертикальному профилю:
   тень гаснет по мере удаления от подошвы, подошва — нет. Тень в габарит не входит.
5. **Размещение.** Кусок исходника сначала масштабируется, габарит измеряется уже в нём, и только
   потом кусок кладётся на холст целочисленным сдвигом. Считать координаты заранее нельзя:
   Ланцош размывает край на пару пикселей, и арифметически «точная» позиция промахивается.
6. **Сохранение.** JPEG качества 100 без субдискретизации, sRGB. Если файл вдруг перевалит за 5 МБ,
   качество ступенчато снижается. На практике кадр 1524 × 2200 весит 0,3…1,3 МБ.

## Чего программа не умеет

* **Отличить вид сбоку от вида подошвы.** У них совпадает силуэт — вытянутое пятно с плоским низом;
  ни текстура, ни симметрия их не разделяют, поэтому оба показываются как «Вид сбоку / подошва».
* **Проверить, что носок смотрит влево.** Признак, работающий для вида сбоку, для подошвы даёт
  обратный ответ (проверено на эталонах — 3 из 3 мимо), а уверенно неверное предупреждение хуже,
  чем его отсутствие. Носок видно в превью — проверяйте глазами.
* **Найти товар, который отличается от фона меньше чем на 5–6 уровней яркости.** Такую границу
  не видит ни один пороговый метод; в этом случае в замечаниях появится «границы товара нечёткие».
* **Подогнать макро-кадр.** Если товар обрезан краем, его настоящих границ не видно, и вписывать
  нечего — см. статус «перенесён без подгонки».

## Разработка

```bash
pip install -r requirements-dev.txt
QT_QPA_PLATFORM=offscreen pytest -q     # включая регрессию на эталонах Ламоды
python app.py                            # запуск интерфейса
pyinstaller --noconfirm --clean LamodaItemFitter.spec
python assets/make_assets.py             # перегенерировать иконку и заставку
```

Структура: `lamoda_item_fitter/` — ядро (не зависит от Qt, поэтому CLI и тесты работают без
интерфейса), `lamoda_item_fitter/gui/` — окно, `presets/` — правила, `reference/` — эталоны,
`tests/` — тесты.
